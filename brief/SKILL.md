# Brief

原理：只写会改变读者判断或行动的内容。格式每次完全一致，降低认知负担。

用于对话里给用户批准，不留档，不写参数。需要留档的实验记录用 exp-report。

## 模板（逐字遵守，4 节始终出现，空节写"无"）

```
【简报·<方案|总结|修改>】<一句话主题>
日期：YYYY-MM-DD ｜ 实验：<实验名 / config / ckpt / commit，适用者>

## 1. 待你决定
1. <问题>？推荐：<A>。备选：<B>（代价：<…>）

## 2. 原理与结论
- 原理：<一句话机制>。例：<具体例子>
- 结论：<带数字 + 对照基线>

## 3. 依据
| <按类型的固定列> |

## 4. 风险与下一步
- 风险：<未验证 / 可能不成立之处>
- 下一步：<批准后做什么>
```

## 第 3 节固定列

| 类型 | 列 | 只列 |
|---|---|---|
| 方案 | 步骤 \| 风险 | 有分歧或风险的步骤 |
| 总结 | 项目 \| 预期 \| 实际 | 偏离预期的项 |
| 修改 | 审稿意见(≤10字) \| 改动 | 每条意见 |

## 条数上限

- 第 1 节 ≤3 条；第 2 节原理 1 句 + 1 例，结论 ≤3 条；第 3 节 ≤5 行；第 4 节风险、下一步各 ≤3 条
- 全文 15–20 行；超出不写，用户追问再展开

## 写什么 / 不写什么

- 写原理：为什么有效（机制、因果链），一句话 + 具体例子。方案类必写；总结、修改类仅在出现新机制时写，否则"无"
- 不写参数：lr、阈值、搜索范围、函数名、文件路径（除非参数本身是待决定项；实验标识只放在抬头行）
- 不写：过程叙述、背景、复述问题、顺利完成无异常的项、填充词（此外/值得注意/总的来说）、客套
- 结论必须带数字和对照：✗ "明显提升" ✓ "BER 4.1%→2.3%（同设置 baseline）"
- 同一信息只出现一次
- 未验证、单 seed、未跑完 → 写进第 4 节风险，不在结论里用模糊措辞

## 用户回复约定

用户按编号回复，如"1.1 同意，1.2 选B"。

## 示例

```
【简报·方案】用 sync_decode 修复 TS+PS 组合攻击失效
日期：2026-10-16 ｜ 实验：combined / dualshield.tar

## 1. 待你决定
1. 解码前加同步估计？推荐：加。备选：重训带 TS 增强的模型（代价：~2 天训练，不保证泛化到 TST）

## 2. 原理与结论
- 原理：时间伸缩使水印帧错位，先用同步码估计伸缩比再反向重采样即可对齐。例：拉长 1.1 倍 → 压回 1/1.1 后解码
- 结论：预估 TS+PS 下 ACC 0.52→0.95 级别（单攻击 TS 已验证 0.97）

## 3. 依据
| 步骤 | 风险 |
|---|---|
| 同步码搜索 | 强 PS 下同步码本身失真，估计可能偏 |

## 4. 风险与下一步
- 风险：解码耗时增加；组合攻击尚未实测
- 下一步：实现后跑 combined 全套攻击
```

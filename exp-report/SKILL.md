# Exp Report

原理：只写会改变读者判断或行动的内容。格式每次完全一致，降低认知负担；留档内容需可追溯。

## 规则

- 追加到当前项目 `doc/experiment_log.md`（不存在则新建）；编号 N 续接文件中最后一个 `## 实验N`
- 5 小节始终出现，空节写"无"
- 允许写路径、脚本名、超参、ckpt（为可追溯）
- N.3 只放数据，不解读；N.4 只解读，不重复列数据
- N.4 原因用一句原理 + 例子；判断不确定的原因标"推测"
- N.5 由 Claude 主动提出下一步（作为 project leader），每条标"（待批）"，用户按编号回复如"3.5.1 同意"
- 写入文件后，对话里只输出：文件链接 + N.4 + N.5
- 禁止：过程叙述、背景、复述问题、填充词（此外/值得注意/总的来说）、客套、同一信息重复

## 模板（逐字遵守）

```
## 实验N：<标题>
日期：YYYY-MM-DD ｜ 实验：<实验名 / config / ckpt / commit>

### N.1 目的
<为什么做，想获得什么；≤2 句>

### N.2 Setting
- 数据：<数据集 / 子集>
- 改动：<相对 baseline 的算法或代码改动>
- 关键超参：<只列与结论相关的>

### N.3 结果记录
- 路径：<log / ckpt>
| <指标表，≤10 行> |

### N.4 分析
- 符合预期：<是 / 否 / 部分>，<一句话哪里不符>
- 原因：<一句原理>。例：<具体例子>（≤3 条）

### N.5 下一步实验
1. <实验> —— 验证：<要回答什么问题>（待批）（≤3 条）
```

## 示例

```
## 实验1：不同容量 training
日期：2026-06-30 ｜ 实验：train_2.py，residual=True

### 1.1 目的
找到 residual=True 时适合不同容量的超参。

### 1.2 Setting
- 数据：LibriSpeech train
- 改动：lambda_m 与 lambda_a 解耦（train_2.py）
- 关键超参：无

### 1.3 结果记录
- 路径：16bit results/log/2026-06-30_22_56_46；32bit …_22_29_50；64bit …_19_51_05；128bit …_22_11_00
| bits | val SNR | acc[time/freq] | 训练 SNR 波动 | msg_loss(ep2) | wav_loss(ep2) |
|---|---|---|---|---|---|
| 16 | 10.94 | 0.9999 / 0.9995 | 3.2~14.3 | 0.070 | 0.00028 |
| 32 | 17.57 | 0.9947 / 0.9996 | 15~19 | 0.118 | 0.000067 |
| 64 | 15.95 | 0.9798 / 0.9988 | 13~18 | 0.182 | 0.000096 |
| 128 | 16.27 | 0.9672 / 0.9899 | 12~16 | 0.289 | 0.000096 |

### 1.4 分析
- 符合预期：部分，16bit SNR 最低且剧烈震荡
- 原因：acc 饱和后 msg_loss 仍主导梯度，wav_loss 压不住。例：ep1 约 2400 步 acc 已达标，之后 SNR 在 3~14 间震荡
- 原因（推测）：lr 偏大、batch 偏小放大梯度噪声

### 1.5 下一步实验
1. 降低 lambda_m —— 验证：acc 饱和后 SNR 能否回升（待批）
2. 增加训练稳定性（降 lr / 增 batch） —— 验证：SNR 震荡是否来自梯度噪声（待批）
```
